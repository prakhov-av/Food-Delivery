# Food Delivery System --- Итог этапа 1 (Архитектура)

## Назначение документа

Этот документ завершает первый этап разработки проекта и служит
отправной точкой для следующих этапов.

## Цель проекта

Разработка REST API для системы доставки еды на NestJS + TypeORM +
PostgreSQL в соответствии с требованиями преподавателя.

## Главный принцип

Сначала реализуем решения так, как они преподаются на курсе. После
завершения курса при необходимости модернизируем проект до промышленного
уровня.

## Архитектура

Структура каждого модуля: - Entity - DTO - Mapper - Repository -
Service - Controller - Module

Цепочка вызовов: Controller → Service → Repository → TypeORM

## Доменная модель

Сущности: - User - Restaurant - Menu - MenuItem - Order - OrderItem

Связи: - Restaurant → Menu (1:1) - Menu → MenuItem (1:N) - Order →
Customer - Order → Courier - Order → Restaurant - OrderItem → Order -
OrderItem → MenuItem

## Принятые соглашения

-   DTO отделены от Entity.
-   Mapper выполняет только преобразование данных.
-   Сервисы обращаются к другим сервисам, а не к чужим Repository.
-   Repository отвечает только за доступ к данным.
-   Контроллеры не содержат бизнес-логики.
-   Во всех модулях единый стиль.
